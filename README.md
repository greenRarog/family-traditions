# Семейный парламент

Семейное приложение на React + TypeScript + Express. Один сервер, JSON-файл семейных данных и отдельный файл сессий, без внешних сервисов.

Без входа открывается описание проекта со ссылкой на GitHub. Кнопка «Войти» справа сверху раскрывает форму семейного пароля. Интерфейс на русском, для телефона и компьютера.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. Заполните три разных пароля и `SESSION_SECRET` (не менее 32 символов; можно сгенерировать командой `openssl rand -hex 32`).
3. Выполните `docker compose up -d --build`.
4. Откройте `http://localhost:8081`. Порт привязан только к loopback; `HTTP_PORT` меняет внешний локальный порт, `PORT` — внутренний.

Данные (`state.json`) и сессии (`sessions.json`) находятся в постоянном Docker volume `parliament-data`. Не запускайте несколько процессов с одним хранилищем. Повреждённый файл никогда не заменяется пустым: сервер отказывается запускаться. Секреты не включаются в сборку клиента и не сохраняются в JSON.

Три пароля должны быть разными и непустыми; пятисимвольные пароли подходят. Требование **не менее 32 символов** относится только к `SESSION_SECRET`, а не к паролю входа.

За HTTPS reverse proxy задайте `COOKIE_SECURE=true`; proxy должен передавать исходный Host. Для локального HTTP оставьте `false`. Изменяющие запросы требуют совпадающий Origin. Лимит входа — 10 неудачных попыток в минуту на IP. `TRUSTED_PROXY` задаёт адрес или CIDR доверенного reverse proxy; в локальной разработке оставьте пустым. Production Compose доверяет только Caddy (`172.30.60.2/32`), который заменяет клиентский `X-Forwarded-For` реальным адресом соединения.

Сессия действует 10 × 365 дней, сохраняется в volume и переживает перезапуск/пересоздание контейнера. Cookie имеет `HttpOnly`, `SameSite=Strict` и в production `Secure`; при загрузке приложения срок cookie обновляется до оставшегося срока сессии. Chrome ограничивает срок cookie 400 днями: при регулярных посещениях она обновляется, после долгого отсутствия или очистки браузера нужен повторный вход. [Ограничение браузера](https://developer.chrome.com/blog/cookie-max-age-expires).

Выход отзывает текущую сессию на диске. Смена пароля участника делает недействительными его старые сессии; смена `SESSION_SECRET` — все сессии. Для перезапуска с сохранением входа нужны прежние секреты и volume. В файле сессий хранятся хеши случайных токенов и HMAC-отпечатки настроек входа, а не пароли или сами cookie. Старые сессии, созданные до этой версии и хранившиеся только в памяти, потребуют одного повторного входа.

## Совместное размещение с my-site

Публичный адрес: `https://family-traditions.konushenko.ru`.

1. В `my-site` запустить `docker compose -f compose.production.yaml up -d --build`: он создаёт Caddy и сеть `personal-web`.
2. Здесь создать и заполнить `.env`, затем выполнить `docker compose -f compose.production.yaml up -d --build`.
3. Использовать production-файл отдельно, не объединять с `compose.yaml`. В нём нет публичного порта приложения; HTTPS и маршрутизацией занимается Caddy.

Volume `parliament-data` сохраняет прежнее имя при неизменном имени Compose-проекта. Если приложение уже запущено локальной конфигурацией, сделать бэкап и остановить его перед переключением. Не использовать `down -v` и не менять `-p` при обновлении.

Полная инструкция: [`my-site/deploy/README.md`](https://github.com/greenRarog/my-site/blob/main/deploy/README.md). Подключение новых проектов, обновление и бэкапы: [`PROJECTS.md`](https://github.com/greenRarog/my-site/blob/main/deploy/PROJECTS.md). В локальных соседних репозиториях эти файлы находятся в `../my-site/deploy/`.

## Правила первой версии (уточнения к исходному tz.md)

- Цикл — от субботы до субботы, граница 00:00 в `TZ` (по умолчанию Europe/Moscow). Среда не ограничивает голосование.
- После проведения или пропуска предыдущей недели можно выбирать следующую субботу. Новое голосование появляется при обращении к серверу. Пропущенные календарные недели не создаются.
- Все три голоса закрывают голосование немедленно. Иначе в субботу сервер при следующем обращении публикует имеющиеся голоса и определяет результат. Клиент проверяет состояние каждые 4 секунды.
- Три голоса: большинство либо равновероятная жеребьёвка; каждый проигравший получает 1 звезду.
- Два разных голоса: равновероятная жеребьёвка; проигравший участник получает 2 звезды за свою карточку. Два одинаковых: общий вариант, без звёзд.
- Один голос выбирает мероприятие без начисления звёзд; ноль голосов означает пропуск.
- Звёзды индивидуальны, максимум 3 на карточку. Все карточки со звёздами участвуют; до 8 добираются случайные карточки без звёзд. Если карточек со звёздами больше 8, участвуют все они.
- Три звезды добавляют карточку в FIFO-очередь гарантированных событий. Одновременное добавление разных карточек упорядочивается однократной жеребьёвкой. Гарантированное событие занимает следующую свободную неделю без голосования.
- Подтверждение проведения доступно всем с даты события; фиксируется дата подтверждения. Обнуляются звёзды всех участников за проведённую карточку, она удаляется из очереди.
- Взрослые могут пропустить неделю. Звёзды сохраняются. Голоса пропущенной до результата недели скрыты до её субботы, затем публичны.
- Непроведённое назначенное событие блокирует новые недели до подтверждения или пропуска. Переносов, импорта и экспорта в первой версии нет.

Статический каталог: `src/domain/catalog.ts`. Локальные SVG-иллюстрации используют системные emoji; их вид зависит от ОС. Инфраструктура приложения не требует доступа в интернет.

## Разработка

Требуется Node.js 22.

```sh
npm ci
node --env-file=.env --import tsx src/server/index.ts
```

В другом терминале: `npm run dev:client`. Vite проксирует API на порт 8080 (для разработки оставьте `PORT=8080`). Для готовой сборки: `npm run build`, затем `node --env-file=.env dist/server.js`.

```sh
npm test
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Доменные тесты используют внедрённые часы и случайность. Серверные тесты проверяют реальную HTTP-авторизацию, тайну голосования, права и сохранность файла. Сквозной тест работает в трёх независимых браузерных контекстах с отдельным тестовым сервером и управляемым временем. Тестовое управление временем отсутствует в production-сервере.

## Проверки перед публикацией

`npm test` проверяет правила голосования, сохранение данных и сессий, выход, смену паролей и лимиты за прокси. `npm run test:e2e` проверяет публичную страницу, раскрытие входа и семейный сценарий в трёх браузерных контекстах. Для системного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/snap/bin/chromium`.

Перед развёртыванием проверить `npm audit`, production-сборку, конфигурацию Compose, HTTPS и сохранение входа после перезапуска на самом VPS. Docker-образ не содержит `.env` и локальные данные.

Проверка зависимостей при подготовке этой версии: `npm audit --omit=dev` — 0 уязвимостей. Полный `npm audit` — 10 (8 moderate, 2 critical) в dev-инструментах: цепочка `typescript-eslint`/`minimatch` и `vitest`/`@vitest/mocker`/`tinypool`. Эти пакеты не устанавливаются в финальный Docker-образ (`--omit=dev`). Обновление тестового стека с переходом на новую основную версию Vitest остаётся отдельной задачей; dev/test-серверы не публиковать наружу.
