# Техническое задание: Family Parliament — Семейный парламент

## 1. Описание проекта

Разработать небольшое семейное веб-приложение для еженедельного выбора совместного семейного досуга посредством тайного голосования.

Состав семьи фиксированный:

- Папа.
- Мама.
- Дочь.

Все участники обладают равными правами при голосовании.

Приложение должно формировать семейную традицию, демонстрировать значимость выбора каждого участника и гарантировать, что регулярно проигрывающие варианты со временем будут реализованы.

Рабочее название проекта: **Family Parliament**.

Язык интерфейса: русский.

## 2. Основные принципы

- Один семейный парламент.
- Ровно три участника.
- Один голос от каждого участника.
- Тайное голосование до получения всех трёх голосов.
- Еженедельный выбор семейного мероприятия.
- Накопление звёзд за проигравшие варианты.
- Гарантированное проведение мероприятия при накоплении трёх звёзд одним участником.
- Минимальная инфраструктурная сложность.
- Отсутствие базы данных и внешних сервисов.
- Возможность голосовать с разных устройств.

Приложение предназначено исключительно для личного семейного использования. Мультитенантность, регистрация новых пользователей и коммерческое использование не предусматриваются.

## 3. Технический стек

### 3.1. Frontend

- React.
- TypeScript со включённым strict mode.
- Vite.
- CSS или Tailwind CSS.
- React Router при необходимости.
- Адаптивная вёрстка.

Не использовать Redux и другие тяжёлые инструменты управления состоянием без объективной необходимости.

### 3.2. Серверная часть

Минимальный HTTP-сервис на Node.js и TypeScript.

Допускается использование Express или Fastify.

Сервер выполняет исключительно следующие функции:

- Авторизация участников.
- Хранение общего состояния приложения.
- Приём голосов.
- Подсчёт результатов.
- Выполнение бизнес-логики накопления звёзд.
- Управление жизненным циклом голосования.
- Экспорт и импорт состояния.
- Раздача статической сборки frontend.

Не использовать Laravel, ORM, SQL, Redis, очереди, отдельные сервисы или базы данных.

### 3.3. Хранение данных

Все изменяемые данные приложения хранятся в одном JSON-файле:

`/data/state.json`

Файл должен содержать:

- Очередь гарантированных событий.

При отсутствии файла приложение автоматически создаёт начальное состояние.

Запись должна быть атомарной: запись во временный файл с последующим переименованием.

Все операции изменения состояния должны выполняться последовательно, исключая потерю данных при одновременном голосовании с нескольких устройств.

При повреждении файла запрещается автоматически заменять его пустым состоянием. Необходимо сохранить повреждённый файл и сообщить об ошибке.

## 7. Жизненный цикл недели

По умолчанию голосование проводится в среду, мероприятие — в субботу.

### 7.1. Открытие голосования

При наступлении среды приложение создаёт новое голосование, если:

- Для текущей недели ещё не существует голосования.
- Предыдущее мероприятие завершено либо неделя явно пропущена.
- Отсутствует гарантированное мероприятие, которое необходимо провести в текущую неделю.

Создание голосования выполняется сервером при первом обращении после наступления соответствующей даты.

Отдельный cron-процесс не требуется.

Идентификатор недели должен однозначно определяться датой среды в настроенном часовом поясе.

Не создавать задним числом голосования за недели, когда приложением не пользовались.

### 7.2. Формирование списка карточек

Из 12 активных карточек для каждого голосования выбирается 8.

Выбор выполняется сервером один раз при создании голосования.

Все участники получают одинаковый список.

Алгоритм:

1. Получить список активных карточек.
2. Определить карточки, за которые хотя бы один участник имеет накопленные звёзды.
3. Включить эти карточки в голосование в первую очередь.
4. Если таких карточек больше восьми, приоритет получают карточки с наибольшим индивидуальным количеством звёзд. При равенстве — карточки с наиболее давним накопленным желанием.
5. Оставшиеся места заполнить случайными карточками из доступного набора.
6. Перемешать итоговый список.
7. Сохранить список в состоянии голосования.

Если активных карточек меньше восьми, использовать все доступные.

Повторная загрузка страницы не должна изменять набор карточек.

Выборка выполняется без повторений.

### 7.3. Голосование

Каждый участник может выбрать одну карточку.

До завершения голосования участник может изменить свой выбор.

Интерфейс должен отображать:

- Список доступных карточек.
- Собственный текущий выбор.
- Статус участия каждого члена семьи.
- Количество проголосовавших из трёх.

Запрещено отображать:

- Чужие голоса.
- Промежуточное количество голосов за карточку.
- Предварительного победителя.
- Любые данные, позволяющие напрямую определить чужой выбор.

Для отправки голоса необходимо явно подтвердить выбор.

После подтверждения третьего голоса голосование автоматически завершается.

### 7.4. Определение победителя

Если одна карточка получила два или три голоса, она становится победителем.

Если все участники проголосовали за разные карточки, проводится случайная жеребьёвка между тремя выбранными карточками.

Вероятность победы каждого варианта одинакова.

Жеребьёвка выполняется сервером один раз.

Результат сохраняется в состоянии приложения.

Повторная загрузка страницы, повторный запрос или перезапуск сервера не должны изменять победителя.

После завершения голосования изменение голосов запрещено.

### 7.5. Публикация результатов

После получения всех трёх голосов одновременно публикуются:

- Победившая карточка.
- Выбор каждого участника.
- Причина победы: большинство или жеребьёвка.
- Начисленные звёзды.
- Дата мероприятия.

Победившая карточка должна быть визуально выделена.

## 8. Механизм накопления звёзд

### 8.1. Основное правило

Звёзды принадлежат конкретному участнику и конкретной карточке.

Нельзя объединять звёзды разных участников.

Пример:

- Папа имеет две звезды за кинотеатр.
- Мама имеет одну звезду за кинотеатр.

Это не считается тремя звёздами и не создаёт гарантированное мероприятие.

### 8.2. Начисление

После завершения голосования каждый участник, проголосовавший за проигравшую карточку, получает одну звезду за неё.

Участники, проголосовавшие за победившую карточку, звёзд не получают.

Звёзды сохраняются между неделями.

Участник не обязан голосовать за одну карточку три недели подряд.

Пример:

- Неделя 1: дочь голосует за океанариум и проигрывает.
- Неделя 2: дочь голосует за кинотеатр.
- Неделя 3: дочь голосует за океанариум и проигрывает.

Результат: две звезды за океанариум.

### 8.3. Гарантированное мероприятие

Когда участник получает третью звезду за одну карточку, соответствующее мероприятие добавляется в очередь гарантированных мероприятий.

Порог составляет три звезды.

Количество звёзд ограничивается этим порогом.

Одна карточка может присутствовать в очереди только один раз, даже если порога достигли несколько участников.

Если одновременно порога достигли несколько разных карточек, порядок между ними определяется однократной случайной жеребьёвкой и сохраняется.

В остальных случаях очередь работает по принципу FIFO.

### 8.4. Проведение гарантированного мероприятия

Если к моменту открытия новой недели очередь гарантированных мероприятий не пуста:

- Обычное голосование не проводится.
- Выбирается первая карточка из очереди.
- Она автоматически назначается мероприятием недели.
- Отображается причина назначения.
- Отображается участник или участники, накопившие три звезды.

Пример сообщения:

«На этой неделе мы отправляемся в океанариум! Дочь трижды голосовала за него, и теперь её желание исполняется».

Назначение гарантированного мероприятия не начисляет новых звёзд.

### 8.5. Списание звёзд

Звёзды списываются только после подтверждения фактического проведения мероприятия.

При проведении мероприятия:

- Обнуляются звёзды всех участников за соответствующую карточку.
- Карточка удаляется из очереди гарантированных мероприятий, если присутствовала в ней.
- Звёзды за остальные карточки сохраняются.

При переносе или отмене мероприятия без его проведения звёзды не списываются.

### 8.6. Отображение звёзд

На карточках необходимо отображать прогресс каждого участника отдельно.

Пример:

Папа: ★★☆

Мама: ★☆☆

Дочь: ☆☆☆

Использовать индивидуальные цвета или аватары участников.

Количество звёзд должно быть понятно ребёнку, не умеющему читать.

## 9. Проведение мероприятия

После завершения голосования приложение переходит в режим ожидания семейного мероприятия.

Отображаются:

- Победившая карточка.
- Название и изображение.
- Полное описание.
- Запланированная дата.
- Обратный отсчёт до даты мероприятия.
- Результаты голосования либо причина гарантированного назначения.

Предусмотреть кнопку «Событие состоялось».

Кнопка доступна любому авторизованному участнику не ранее запланированной даты мероприятия.

Перед подтверждением показать диалог.

После подтверждения:

1. Мероприятие получает статус завершённого.
2. Фиксируется дата фактического проведения.
3. Списываются соответствующие звёзды.
4. Обновляется очередь гарантированных мероприятий.
5. Запись сохраняется в истории.

Повторное подтверждение не должно повторно изменять состояние.

### 9.1. Перенос

Взрослый участник может перенести мероприятие на другую дату.

При переносе сохраняются:

- Результаты голосования.
- Победившая карточка.
- Начисленные звёзды.
- Очередь гарантированных мероприятий.

### 9.2. Пропуск недели

Взрослый участник может явно пропустить незавершённую неделю.

Необходимо запросить подтверждение.

Если голосование не завершено, оно закрывается без победителя и без начисления звёзд.

Если победитель уже определён, начисленные за голосование звёзды сохраняются, но звёзды за непроведённое мероприятие не списываются.

Гарантированное мероприятие остаётся в очереди.

Следующая неделя может начаться в соответствии с обычным расписанием.

## 10. Состояния голосования

Предусмотреть следующие состояния:

- `open` — голосование открыто.
- `scheduled` — победитель определён, мероприятие запланировано.
- `completed` — мероприятие состоялось.
- `skipped` — неделя пропущена.

Тип выбора мероприятия:

- `majority` — победа большинством.
- `lottery` — победа в жеребьёвке.
- `guaranteed` — гарантированное мероприятие.

Допустимые переходы:

- `open → scheduled`
- `open → skipped`
- `scheduled → completed`
- `scheduled → skipped`

Гарантированное мероприятие создаётся сразу в состоянии `scheduled`.

Перенос даты не изменяет состояние `scheduled`.

Переходы из `completed` и `skipped` запрещены.

Не допускается существование нескольких одновременно незавершённых недель.

## 11. История

Сохранять техническую историю всех голосований и мероприятий.

Для каждой недели хранить:

- Идентификатор.
- Дату создания.
- Список предложенных карточек.
- Голоса участников.
- Победителя.
- Тип определения победителя.
- Начисленные звёзды.
- Первоначальную дату мероприятия.
- Актуальную дату мероприятия.
- Дату фактического проведения.
- Итоговый статус.

Для незавершённых и пропущенных до публикации голосований сохранять конфиденциальность чужих голосов.

Предусмотреть простую страницу истории с хронологическим списком недель.

Не реализовывать:

- Загрузку фотографий.
- Комментарии.
- Семейный фотоархив.
- Социальные функции.

## 12. Экспорт и импорт

Предусмотреть возможность скачать состояние приложения в формате JSON.

Имя файла:

`family-parliament-backup-YYYY-MM-DD.json`

Экспорт содержит:

- Версию схемы.
- Текущее состояние.
- Историю.
- Звёзды.
- Очередь гарантированных мероприятий.

Экспорт не содержит паролей, токенов и сессионных данных.

Экспорт полного состояния доступен взрослым участникам только при отсутствии незавершённого тайного голосования. Это необходимо для сохранения тайны голосования.

Импорт доступен взрослым участникам.

Перед импортом:

1. Проверить формат JSON.
2. Проверить версию схемы.
3. Проверить структуру и целостность данных.
4. Проверить идентификаторы участников и карточек.
5. Запросить подтверждение замены текущего состояния.
6. Создать резервную копию текущего состояния.
7. Атомарно заменить состояние.

При ошибке импорта текущее состояние не должно изменяться.

Импорт запрещён во время открытого голосования.

## 16. Безопасность тайного голосования

До завершения голосования сервер возвращает только:

- Идентификатор текущего голосования.
- Список карточек.
- Собственный голос авторизованного участника.
- Статусы участия остальных участников.
- Звёзды, накопленные в предыдущих голосованиях.

Полный объект внутреннего состояния не должен возвращаться напрямую через API.

Необходимо реализовать отдельное преобразование внутреннего состояния в публичное представление для конкретного участника.

Файл `state.json` не должен находиться в директории статических файлов.

Запрещено записывать в логи пароли и содержимое тайных голосов.

Операции изменения состояния защищаются от CSRF посредством проверки Origin и подходящих настроек сессионной cookie либо отдельного CSRF-токена.

## 19. Требования к тестированию

Использовать Vitest для unit- и integration-тестов.

Для основных пользовательских сценариев использовать Playwright.

Приоритет — тестирование бизнес-логики и сохранности состояния.

### 19.1. Голосование

Проверить:

- Победу двумя голосами.
- Единогласную победу.
- Жеребьёвку при трёх разных голосах.
- Изменение голоса до завершения голосования.
- Запрет изменения после завершения.
- Запрет выбора отсутствующей в голосовании карточки.
- Отсутствие повторного определения победителя.
- Одновременную отправку голосов с разных устройств.
- Запрет голосования за другого участника.
- Запрет изменения завершённого голосования.

### 19.2. Тайна голосования

Проверить:

- После первого голоса чужой выбор недоступен.
- После второго голоса чужой выбор недоступен.
- После третьего голоса результаты доступны всем.
- До завершения отсутствуют промежуточные результаты.
- История не раскрывает незавершённые тайные голоса.
- Экспорт запрещён во время открытого голосования.
- Пропущенное незавершённое голосование не раскрывает чужие голоса.

### 19.3. Звёзды

Проверить:

- Начисление одной звезды проигравшему участнику.
- Отсутствие начисления победителям.
- Независимость звёзд разных участников.
- Сохранение звёзд между неделями.
- Создание гарантированного мероприятия при третьей звезде.
- Отсутствие дубликатов в очереди.
- Обработку нескольких гарантированных мероприятий.
- Списание звёзд только после фактического проведения.
- Сохранение звёзд при переносе.
- Сохранение звёзд при пропуске.
- Отсутствие повторного начисления при повторном запросе.

### 19.4. Случайная выборка карточек

Проверить:

- Выбор восьми карточек из двенадцати.
- Отсутствие дубликатов.
- Исключение неактивных карточек.
- Приоритет карточек с накопленными звёздами.
- Обработку случая, когда приоритетных карточек больше восьми.
- Обработку случая, когда активных карточек меньше восьми.
- Неизменность выборки после перезапуска.

### 19.5. Расписание

Проверить:

- Создание голосования в среду.
- Отсутствие повторного создания.
- Назначение мероприятия на субботу.
- Приоритет гарантированного мероприятия.
- Блокировку новой недели при наличии незавершённой.
- Корректность работы часового пояса.
- Отсутствие создания пропущенных недель задним числом.

### 19.6. Хранилище

Проверить:

- Создание начального состояния.
- Восстановление после перезапуска.
- Атомарность записи.
- Одновременное изменение состояния.
- Экспорт и импорт.
- Отказ при импорте некорректных данных.
- Сохранение текущего состояния при ошибке.
- Обработку повреждённого файла.

### 19.7. Сквозной сценарий

Реализовать автоматизированный сценарий:

1. Три участника авторизуются в отдельных браузерных контекстах.
2. Каждый получает одинаковый набор карточек.
3. Дочь голосует за океанариум.
4. Родители голосуют за пиццерию.
5. До третьего голоса результаты скрыты.
6. Побеждает пиццерия.
7. Дочь получает одну звезду.
8. Пиццерия подтверждается как проведённая.
9. Сценарий повторяется до накопления трёх звёзд.
10. На следующей неделе автоматически назначается океанариум.
11. После его проведения соответствующие звёзды обнуляются.

Для тестирования расписания использовать внедряемый источник времени.

Для тестирования случайных операций использовать внедряемый генератор случайных чисел.

Не использовать реальные ожидания наступления календарных дат в тестах.

- Чужой выбор скрыт до завершения голосования.
- Победитель определяется ровно один раз.
- Звёзды начисляются ровно один раз.
- Три звезды гарантируют проведение мероприятия.
- Звёзды списываются только после фактического проведения.
- Ни один голос не должен теряться при одновременной работе нескольких устройств.
